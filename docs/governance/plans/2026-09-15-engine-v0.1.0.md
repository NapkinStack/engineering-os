# NapkinStack engine v0.1.0 — implementation plan

> **Location:** `docs/governance/plans/`, the repository's working context; no folder
> named after a tool (P2, P7).
>
> **For the executing agent:** run workstream by workstream, task by task, in TDD. The
> steps use checkboxes (`- [ ]`) for tracking. A workstream receives its detailed plan
> here when it starts, informed by what the previous one learned: M1, M2a, M2b, M3, M3.1,
> M3.2, M4, M6, M6.1 and M5 (done), then the pilot project.
>
> **On this document's form.** Every workstream below is closed and merged. When it was
> translated to English (workstream M7, 2026-09-16), the long verbatim code excerpts —
> 2 357 of its 3 654 lines, snapshots of files that have since been rewritten — were
> replaced by a sentence stating what each step did. The decisions, the verified facts,
> the dates, the measured numbers, the pull request numbers and the gaps observed during
> execution are kept as they were. The exact code of the time remains in git history.

**Goal:** publish `napkinstack` v0.1.0 on PyPI, able to create a project (`nstack init`),
update it (`nstack update`) and check it (`nstack doctor`), then use it for the pilot
project before 2026-10-31.

**Architecture:** a single repository. The engine is a Python package
(`src/napkinstack/`, `uv_build`); the project skeleton is the repository's only Copier
template (`copier.yml`, `_subdirectory: skeleton`); NapkinStack's own development context
(`PRODUCT.md`, `docs/governance/`, the repository's CI) stays at the root and is never
copied.

**Technical stack:** Python ≥ 3.12 managed by uv, PyYAML, Copier 9.18, pre-commit, GitHub
Actions.

**Specification:** [PDR-0001](../../pdr/0001-create-a-project-and-receive-updates.md)
(accepted), [ADR-0001](../../adr/0001-adopt-copier-to-generate-and-update-projects.md)
(accepted), [ADR-0002](../../adr/0002-distribute-napkinstack-on-pypi.md) (accepted).

## Global constraints

- uv is the only prerequisite; no stack imposed on the modules (PDR-0001 R5,
  `PRODUCT.md` P1).
- One version covers the engine and the skeleton; the project pins its own (PDR-0001 R2,
  R3).
- Copier driven by `run_copy` and `run_update`, never `unsafe`; a single template in this
  repository (ADR-0001).
- The `napkinstack` package, the `nstack` command, `uv_build`, the version in
  `pyproject.toml` equal to the tag `vX.Y.Z` (ADR-0002).
- Third-party actions allowed: `astral-sh/setup-uv` and `pypa/gh-action-pypi-publish`,
  pinned by SHA (ADR-0002).
- Hooks and CI run the same configuration (P3); every check has a test that proves it
  fails (P5); every failure names the rule, the place and the action (P6).
- One workstream = one pull request; a review budget of 400 lines and 15 files, with the
  over-budget label justified for a mechanical migration.
- Identity: commits `fc <328672623+napkinstack-admin@users.noreply.github.com>`, pushes
  through the SSH alias `github-napkinstack`, the GitHub API through `gh-napkinstack`.

## M2b — `nstack init` and `nstack update` (done, #15)

**Workstream decisions** (facts verified on 2026-09-15, prototype on the real skeleton):

| Subject | Choice | Reference, verified fact |
|---|---|---|
| Target version | `--ref` defaults to `v<nstack version>`: engine and skeleton move up together (R2); changing version means installing the version you want, then `nstack update` | Rails: the installed generator fixes the template's version. `uv tool install napkinstack==X` reinstalls another version (observed with another tool). Going backwards refused natively by Copier: `You are downgrading from … to …` |
| Source | `--source`, defaulting to `https://github.com/NapkinStack/engineering-os.git`; `update` re-reads `_src_path` from the answers file | Copier records the source at creation |
| `init` | A missing or empty folder; the `copier.yml` questions as options, asked when absent; then `git init --initial-branch=main`, `git add --all` and an initial commit | `rails new`: `git init`, `git add .`, an initial commit. `main`: the branch of the skeleton's workflows |
| `update` | Copier first, on the committed state; when there are changes, `git switch --create nstack/update-<ref>` carries them; with no conflict, a commit; with a conflict, nothing is committed | Prototype: Copier leaves the changes unstaged and marks conflicts as unmerged (`UU`), listed by `git diff --name-only --diff-filter=U`. `git add --all` then a commit accepts markers without a hook: nstack therefore never commits a conflict, and the hook and CI refuse it |
| Refusals | A modified tree, a downgrade, a project outside git, an unpublished origin version, an "unsafe" template: Copier's refusals, before any change, translated into P6 messages | Messages read in `copier/_main.py`; a missing version raises `ProcessExecutionError` (a subclass of `OSError`), a missing source raises `ValueError` |
| Loading | Copier imported only by `init` and `update` | Importing Copier: 0.2 s, against 0.04 s for the whole current CLI; `nstack fitness` does not slow down |
| Tests | Inside `platform/tests/run.sh`, through `nstack init`: M2a's skeleton section goes through the command, then a throwaway template with three tags covers criteria 4 to 7 | The same oracle as M1 and M2a, with no extra test tool |
